# DDL Reminder 产品需求

## 1. 项目目标

开发一个运行于 Windows 11 的桌面任务管理应用。

项目有两个目标：

1. 解决我经常忘记课程作业、报名和其他 DDL 的问题。
2. 作为恢复 Python 编码能力和学习工程开发能力的实践项目。

本项目优先保证：

- 功能真实可用
- 代码职责清晰
- 核心逻辑可测试
- 架构不过度复杂
- 我能够理解和解释每一项核心实现

## 2. 产品形态

应用包含两个主要界面：

### 主窗口

用于：

- 创建任务
- 编辑任务
- 完成任务
- 删除任务
- 查看进行中任务
- 查看已完成任务
- 恢复已完成任务

### 悬浮窗

用于：

- 始终置顶显示
- 显示最紧迫的三个未完成任务
- 展示任务标题、DDL 和剩余时间
- 显示逾期状态
- 点击任务时打开主窗口

## 3. 任务字段

每个任务至少包含：

- 唯一 ID
- 标题
- 可选描述
- DDL 日期
- 可选 DDL 时间
- 是否完成
- 完成时间
- 创建时间
- 更新时间
- 是否已发送 24 小时提醒
- 是否已发送 1 小时提醒

## 4. DDL 规则

- 日期必填。
- 时间可选。
- 未填写时间时，默认当天 23:59。
- 已过期任务继续显示。
- 已过期任务优先于未过期任务。
- 未完成任务按照 DDL 从早到晚排序。
- 悬浮窗最多显示三个任务。
- 已完成任务不出现在悬浮窗和进行中列表中。
- 已完成任务保留在已完成页面。
- 已完成任务可以恢复。
- 删除操作会真正删除数据库记录。

## 5. 时间显示规则

根据当前时间和 DDL 显示：

- 已逾期 X 天
- 已逾期 X 小时
- 剩余 X 天
- 剩余 X 小时
- 剩余 X 分钟

具体边界由领域逻辑统一处理，不允许各个 UI 自己计算。

## 6. 通知规则

Windows 系统通知包括：

- 到期前 24 小时提醒一次
- 到期前 1 小时提醒一次
- 每类提醒不能重复发送
- 已完成任务不再提醒
- 程序未运行而错过提醒时，下次启动进行补发
- 通知失败时记录日志，不应导致整个程序退出

## 7. 启动行为

- 支持 Windows 开机自动启动。
- 自动启动后默认隐藏主窗口。
- 自动启动后显示悬浮窗。
- 程序常驻系统托盘。
- 托盘菜单可以打开主窗口、显示或隐藏悬浮窗、退出程序。

## 8. 数据存储

- 使用本地 SQLite 数据库。
- 数据库应保存在 Windows 用户数据目录。
- 程序升级时不能覆盖用户数据库。
- 数据库结构变化应使用迁移管理。


## 补发规则：

- 如果程序启动时发现任务尚未完成、尚未过期，并且已经进入 24 小时提醒窗口，则发送 24 小时提醒。
- 如果程序启动时发现任务尚未完成、尚未过期，并且已经进入 1 小时提醒窗口，则发送 1 小时提醒。
- 如果任务已经过期，不再补发 24 小时或 1 小时提醒。
- 每种提醒是否已经发送，记录在 Task 上。
- 是否应该发送提醒由领域逻辑判断，实际 Windows 通知由提醒服务负责。
- 剩余23小时58分钟，显示“剩余23h”，剩余59s，显示剩余“0分钟”
- now >= deadline 算逾期

## 9. 第一版不做

- 用户账号
- 云同步
- 多设备同步
- 手机端
- Web 端
- 多人协作
- Redis
- 消息队列
- 微服务
- 复杂插件系统
- 自定义提醒规则
- 复杂动画和主题系统

## 10. 完成标准

第一版完成后，用户应该能够：

1. 创建带有 DDL 的任务。
2. 重启应用后仍然看到任务。
3. 在桌面悬浮窗看到最紧迫的三个任务。
4. 清楚看到任务还剩多久或逾期多久。
5. 在任务完成后将其移入已完成列表。
6. 恢复或者彻底删除任务。
7. 收到 24 小时和 1 小时 Windows 通知。
8. 在 Windows 登录后自动运行应用。
9. 将项目打包成可运行的 Windows 程序。
