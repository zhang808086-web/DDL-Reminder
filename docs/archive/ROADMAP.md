# DDL Reminder 开发路线

## 工作规则

每个阶段都采用：

1. 明确需求和边界。
2. 我先设计接口。
3. Codex 只做设计评审。
4. 我编写第一版。
5. Codex 做代码审查。
6. 我自己修改。
7. 我编写测试。
8. Codex 检查测试覆盖。
9. 阶段完成后再进入下一阶段。

未经明确要求，不提前实现后续阶段。

## Phase 1：领域逻辑

目标：

- 定义 Task
- 规范化 DDL
- 判断逾期状态
- 格式化剩余时间
- 判断提醒区间
- 编写领域单元测试
- 明确提醒触发与补发判断规则，并通过传入 now 进行测试

完成标准：

- 不依赖 PySide6
- 不依赖数据库
- 所有时间计算可以通过传入 now 测试
- 边界情况有测试

当前状态：已完成

## Phase 2：内存版任务服务

目标：

- 定义 TaskRepository 接口
- 实现内存 Repository
- 实现 TaskService
- 创建、编辑、完成、恢复和删除任务
- 获取最近三个紧迫任务
- 编写 Service 单元测试

当前状态：已完成

## Phase 3：SQLite 持久化

目标：

- 配置 SQLAlchemy
- 创建数据库模型
- 实现 SQLAlchemyTaskRepository
- 使用临时 SQLite 编写集成测试
- 确认重启后数据保留

当前状态：已完成

## Phase 4：主窗口

目标：

- 显示进行中任务
- 创建和编辑任务
- 完成和删除任务
- 显示已完成任务
- 恢复任务

当前状态：已完成

## Phase 5：悬浮窗

目标：

- 始终置顶
- 显示最近三个任务
- 显示剩余或逾期时间
- 定时刷新
- 点击任务打开主窗口
- 保存窗口位置

当前状态：已完成

## Phase 6：提醒系统

目标：

- 24 小时提醒
- 1 小时提醒
- 防止重复提醒
- 启动时补发
- 通知失败日志

当前状态：已完成

## Phase 7：Windows 集成

目标：

- 系统托盘
- 开机自动启动
- 主窗口默认隐藏
- 托盘退出
- 单实例运行

当前状态：已完成

## Phase 8：工程完善

目标：

- Alembic 迁移
- 日志
- 配置管理
- 自定义异常
- ruff
- 类型检查
- pytest
- PyInstaller
- README
- 发布包

当前状态：已完成
